# STM32F411 TIM PWM + DMA 模拟 WT588F02B-8S 单线串口实验

## 项目说明

##### 项目简介

本仓库是一个基于 STM32Cube HAL 的嵌入式实验工程。工程使用 STM32F411CEU6 的 TIM2 PWM 与 DMA，在 PA0 上生成 WT588F02B-8S 所需的单线串口控制波形，并演示连续播放语音地址 `0x00`、`0x01` 和 `0x02`。

##### 主要功能

- 将起始电平、8 位数据和字节间隔编码为 PWM 比较值，数据按低位在前发送。
- 由 TIM2 更新事件触发 DMA，将波形缓冲区写入 `TIM2_CCR1`；DMA 传输完成中断负责通知上层。
- 以一组连续播放指令为单位启停 PWM，示例循环发送 `F3 + 0x00/0x01/0x02`。
- 提供可直接使用的 Keil 工程、CubeMX 配置和相关协议资料。

## 工程使用指南

##### 环境与依赖

必需硬件：

- STM32F411CEU6 开发板（工程使用 25 MHz HSE）
- WT588F02B-8S 语音模块、匹配的供电与音频输出设备
- SWD 下载器（J-Link 或 ST-Link）及连接线

工程记录的软件环境如下：

| 软件/组件 | 版本 |
| --- | --- |
| Keil MDK-ARM | V5.32 |
| Arm Compiler 5 | V5.06 update 7 (build 960) |
| STM32CubeMX（仅重新配置时需要） | 6.16.1 |
| STM32CubeF4 | 1.28.3（HAL 1.8.5） |
| Keil STM32F4xx DFP | 2.17.1 |

可选工具：逻辑分析仪用于核对 PA0 波形；USB 转串口模块用于查看调试输出。

##### 硬件连接与配置

| STM32F411CEU6 | 外部连接 | 说明 |
| --- | --- | --- |
| PA0 / TIM2_CH1 | WT588F02B-8S 单线数据输入端 | PWM 控制信号 |
| GND | 语音模块 GND | 必须共地 |
| PA9 / USART1_TX | USB 转串口 RX（可选） | 115200、8-N-1 |

语音模块应按其规格供电并连接匹配的扬声器或功放；上电前请确认模块已配置为单线串口模式，且语音地址 `0x00`～`0x02` 已写入有效音频。SWD 下载器按所用开发板的标准 SWD 接口连接。

工程中的关键外设参数：

| 项目 | 配置 |
| --- | --- |
| 系统时钟 / TIM2 时钟 | 100 MHz / 100 MHz |
| TIM2 | 预分频 99，自动重装载值 799，周期 800 μs |
| 比较值 | `0`、`200`、`600`、`800`，分别生成低电平、25%、75% 和高电平 |
| DMA | DMA1 Stream1 / Channel 3，存储器到外设，Normal 模式，字宽 32 bit |
| DMA 触发与目标 | TIM2 Update → `TIM2_CCR1` |

##### 编译、运行与观测

1. 完成上述接线，打开 `MDK-ARM/STM32F411CEU6.uvprojx`。
2. 在 Keil 中选择 `STM32F411CEU6` Target，编译工程并通过 SWD 下载到开发板。
3. 复位开发板。程序等待语音模块上电稳定后，发送 `F3 + 0x00/0x01/0x02` 连续播放序列；每轮结束后等待约 5 秒，再次发送。
4. 通过扬声器确认三段语音按地址顺序播放。可选地连接串口查看每轮发送后的 `TEST 1142!`，或使用逻辑分析仪检查 PA0 的起始电平、数据位和字节间隔。

##### 移植说明

- 更换时钟或定时器后，需要重新计算预分频、自动重装载值及比较值，保持当前 1 μs 计数分辨率和 800 μs 波形周期，或按目标协议重新设计时序。
- 更换引脚或定时器通道时，需要同步修改 GPIO 复用、`TIM_CHANNEL_x`、目标 `CCRx`，以及 DMA 请求、Stream、Channel、IRQ 和句柄关联。
- 波形缓冲区为 `uint32_t`，DMA 的存储器与外设数据宽度必须保持一致；若扩展指令长度，应同时检查缓冲区长度和 SRAM 占用。
- 当前播放地址和等待流程写在 `BSP/bsp_wt588f02b_8s/bsp_wt588f02b_8s.c` 中；移植到 RTOS 或非阻塞框架时，可将忙等待替换为任务通知或事件机制。
- 本仓库仅验证了 STM32F411CEU6、TIM2_CH1/PA0 和 DMA1 Stream1/Channel 3 的组合，其他平台需要重新验证波形与电气兼容性。

## 作者思考

##### 项目关联思考

###### 背景

>在使用 WT588F02B 语音模块以及 DHT11 这类单总线通信模块时，通常会使用以下两种方法来进行通信：
>
>1. 使用 GPIO 加 Delay 延时来模拟通信时序。
>2. 使用定时器 PWM 产生所需的方波。
>
>但这两种方法都存在一定的问题：GPIO 加 Delay 中长期使用延时会导致阻塞，降低了系统的实时性；而定时器 PWM 则需要 CPU 不停地更新定时器的 CCR，以产生所需的不同占空比方波，对 CPU 的消耗依旧非常高。
>
>因此，我们引出了第三种方法：定时器 PWM 加 DMA。
>
>即使用 DMA 将需要更新的 CCR 寄存器值从 SRAM 搬运到定时器的 CCR 寄存器。我们不需要打开定时器的中断，只需配置好定时器的 DMA 功能：
>
>• 定时器的 update 事件触发 DMA 更新请求。
>• DMA 将 SRAM 的 buffer 缓冲区中的数值搬运到定时器的 CCR 寄存器中。
>• 寄存器依据该数值产生不同占空比的方波。
>
>当一次完整的数据发送完成后，DMA 会产生 TC 中断，进而触发其完成回调函数，更新传输完成事件。
>
>这种方法解决了 GPIO 加 delay 的阻塞，也解决了传统定时器 PWM 产生方波的 CPU 高消耗，但是并没有发挥 CPU 的 ALU、FPU 等运算能力。
>
>它解放了 CPU，提高了系统实时性。

###### 重要BUG记录

>**现象描述**:最初播放函数放在 WT588 初始化结束之后，经常不播放，需要反反复复复位，偶尔只能成功一次。
>
>将播放函数放入 while 循环，延时 2 秒，出现随机播放、重复播放、顺序混乱和间隔不一致。
>
>延时改成 5 秒后，偶尔只能播放一个音频。

> **排查**:
>
> 1. 查找手册，确认过播放指令 F3 00、F3 01、F3 02 正确。硬件无问题，硬件 demo 测试版能正常播放。
>
> 2. 用逻辑分析仪检测 MCU 与驱动板之间的通信，检查发现：起始电平正常，定时器和 DMA 搬运能力没有问题，*但是在每个字节发送结束后，高电平只保持了 12-14 微秒，远远没有达到参考协议要求的 5-10 毫秒。*
>
> 3. 检查代码发现，DMA 发送完一个字节后都会进入回调，并在回调中执行 HAL_TIM_PWM_Stop。
>
>    定时器关闭后，后面的HAL_Delay(2);HAL_Delay(5);根本起不到作用。

> **解决方案**:
>
> 1. 优化定时器启停逻辑：
>
>    我放弃了在每发送完一个字节就在 DMA 回调中关闭定时器的方式，改为以一次完整的连码发送事务为单位进行控制。
>
>    比如，我在发送 F3 00、F3 01、F3 02 前启动定时器，发送结束之后再关闭定时器。这样既避免了频繁的启停造成时序异常，也减少了空闲期间的功耗。
>
> 2. 简化 DMA 回调逻辑:
>
>    DMA 传输完成后，只负责清除 BZ 标志，通知上层当次发送完成，不再关闭定时器。
>
>    定时器由上层流程在确认整组时序全部完成后统一关闭。
>
> 3. 将完整的通信时序都写入到这个 DMA 缓冲区中:
>
>    我们直接将协议要求的所有电平直接编码到 DMA 发送数组中，包括：
>
>    - 起始低电平
>    - 参数传入进来的 8 位数据波形
>    - 字节之间的高电平间隔
>    - 最后一个字节结束后的高电平
>
>    然后删除字节之间的 HAL_Delay() 延时，由定时器和 DMA 统一生成完整时序，避免软件延时及定时器启停造成电平错误。

##### 项目弱关联思考

使用 DMA 加定时器，此种方案可以用于以后拓展至其他通讯协议的软件模拟。
