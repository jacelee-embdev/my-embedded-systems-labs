# STM32F411 FreeRTOS 队列传值与传指针中断耗时对比实验

## 项目说明

##### 项目简介

本项目基于 STM32F411CEU6 和 FreeRTOS，对比中断服务函数中使用 `xQueueSendFromISR()` 传输结构体值与结构体指针的耗时。逻辑分析仪采集按键输入和 GPIO 追踪信号，用于观察两种方式的差异。

##### 主要功能

- 通过编译开关选择“传值”或“传指针”实现。
- 通过 `test_payload` 调整事件结构体大小。
- 由 PA0 触发按键中断，并在 PB12 输出测量标记。

##### 仓库结构

```text
.
├── BSP/key/             # 按键队列的传值与传指针实现
├── BSP/led/             # LED 驱动与任务

├── Middlewares/         # FreeRTOS 源码
├── MDK-ARM/             # Keil 工程文件
└── STM32F411CEU6.ioc    # STM32CubeMX 配置
```

## 工程使用指南

##### 环境与依赖

| 类型 | 配置 |
|---|---|
| MCU | STM32F411CEU6，100 MHz |
| RTOS / 固件包 | FreeRTOS V10.3.1、STM32Cube FW_F4 V1.28.3 |
| 工具链 | Keil MDK-ARM 5、ARM Compiler 5.06 update 7 |
| 硬件工具 | SWD 下载器、逻辑分析仪 |

工程已包含 HAL、CMSIS 和 FreeRTOS 源码。

##### 硬件连接与配置

| 信号 | 引脚 | 用途 |
|---|---|---|
| KEY1 | PA0 | 上拉输入，下降沿触发 EXTI0 |
| INT_TRACE | PB12 | 推挽输出，向逻辑分析仪提供测量标记 |
| GND | GND | 开发板与逻辑分析仪共地 |

逻辑分析仪至少连接 PA0、PB12 和 GND。

##### 编译、运行与观测

1. 使用 Keil 打开 `MDK-ARM/STM32F411CEU6.uvprojx`。
2. 在 `BSP/key/inc/bsp_key_config.h` 中选择传输方式：

   ```c
   #define BSP_KEY_QUEUE_USE_POINTER    (0U)
   ```

   - `0U`：使用 `bsp_key_queue_value.c/.h`，队列传输完整结构体。
   - `1U`：使用 `bsp_key_queue_pointer.c/.h`，队列传输结构体指针。

3. 在两套头文件中将 `test_payload` 设置为相同长度；测试 8 Byte 基准时同时注释该数组。
4. 执行 Rebuild，下载固件，然后按下 KEY1。
5. 使用逻辑分析仪测量 PA0 下降沿到 PB12 翻转沿的时间，并分别记录两种模式的结果。

> 当前传指针实现复用一个静态事件对象，仅适合本项目的受控实验；用于高并发场景时应改用对象池或其他具有明确所有权的缓冲方案。

##### 移植说明

移植到其他芯片或开发板时，需要重新配置系统时钟、KEY1 和 INT_TRACE 引脚，并检查 EXTI 中断优先级是否满足 FreeRTOS 要求。不同编译器的枚举大小和内存对齐方式可能改变结构体大小，因此移植后应重新测量。

## 实验报告

##### 1. 实验背景与原理

1. 中断服务函数（ISR）往往要求快进快出，而且是非阻塞式的。因此，我们往往只在中断服务函数中进行很轻量的操作，比如改变某个事件的标志位等等。
2. 很多时候，我们需要对中断服务函数中的程序进行优化，缩短它的时间，使得整个系统的性能得到提升。
3. 我们在某段程序执行开始之前，将追踪它的 GPIO pin 脚设置为高电平，执行结束后配置为低电平。使用逻辑分析仪来检测这个脉冲的时长，近似代替这段程序的运行时间。
4. **FreeRTOS 队列的实现原理是基于值拷贝**。在传输大量数据的时候，传指针的方式，其性能将会比直接传原始数据的方式得到提高。

##### 2. 实验假设

假设 在 FreeRTOS 的中断服务函数中，使用 xQueueSendFromISR 传原始数据的指针所消耗的时间 

小于 

传原始数据的值。

##### 3. 实验平台与配置

- STM32F4211CEU6
- Keil MDK

##### 4. 变量与控制条件

- 自变量 1:使用 FreeRTOS 的队列传输数据时，对象是原始数据的值，还是原始数据的指针
- 自变量 2:所需要传输数据对象的大小
- 因变量:中断服务函数 IRQ 的程序运行 时长
- 控制变量:其他所有变量都一致

##### 5. 实验步骤

分别测量“传值”和“传指针”两种情况下:所需要传输的数据对象的大小从 8 字节开始，逐步增大到 136 字节、264 字节、408 字节，记录中断服务函数 IRQ 的程序运行时长。

##### 6. 实验数据、分析与结论

| 测试情况（结构体总大小）                 |     传值 |   传指针 |   降低量 | 降低率 | 平均每 Byte 降低 |
| ---------------------------------------- | -------: | -------: | -------: | -----: | ---------------: |
| 基准：注释掉数组（8 Byte）               | 10.85 µs | 10.85 µs |     0 µs |     0% |                0 |
| `uint32_t test_payload[32]`（136 Byte）  | 20.40 µs | 10.85 µs |  9.55 µs | 46.81% |   0.0746 µs/Byte |
| `uint32_t test_payload[64]`（264 Byte）  | 29.30 µs | 10.85 µs | 18.45 µs | 62.97% |   0.0695 µs/Byte |
| `uint32_t test_payload[100]`（408 Byte） | 39.40 µs | 10.85 µs | 28.55 µs | 72.46% |   0.0701 µs/Byte |

结构体越大，传指针的收益越明显：408 Byte 时延迟降低 28.55 µs，降低率为 72.46%。基于本次 PC、逻辑分析仪、MCU 和软件配置，结构体每增加 1 Byte，传指针相较传值平均约减少 **0.071 µs**。该数值只描述本次数据的变化趋势，不是跨平台固定指标。

##### 7. 误差与局限性

所得数据的大小和精度，受被测 MCU 板子的性能、逻辑分析仪的采样率影响。数据上可能会存在一定的误差，但假设得到了验证。

##### 8. 作者思考

在现实开发中，如果我们涉及大量数据的传输，尤其是在使用到 FreeRTOS 的队列发送 API 的情况下，更尤其是在中断中发送，建议使用“传指针”的方式进行优化。

通过指针进行这种近似“零拷贝”的方式进行优化，能够降低程序运行时间,有效提升程序的性能。
