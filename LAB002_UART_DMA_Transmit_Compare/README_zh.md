# STM32F411 串口中断与 DMA 接收耗时对比实验

## 项目说明

##### 项目简介

本工程比较 STM32F411 使用 USART 中断（IT）与 DMA 接收时的 CPU 开销，以及两种方式对主循环业务耗时的影响。

##### 主要功能

- 通过一个宏切换 IT 与 DMA 接收模式；
- 使用二维数组搬运模拟持续业务负载；
- 通过三个 GPIO 测量主循环、IRQ Handler 和 Callback 的耗时。

##### 仓库结构

```text
Core/       应用代码与中断处理
Drivers/    STM32 HAL 与 CMSIS
MDK-ARM/    Keil 工程
*.ioc       STM32CubeMX 配置
README*     中英文说明文档
```

## 工程使用指南

##### 环境与依赖

STM32F411CEU6、STM32Cube FW_F4 V1.28.3、Keil µVision 5.38、串口助手和逻辑分析仪。

##### 硬件连接与配置

USART1 使用 PA9/PA10；逻辑分析仪连接 PB4（主循环）、PB5（Callback）、PB6（IRQ）和 GND。接收模式在 `Core/Inc/usart.h` 中选择：

```c
/* 1：IT 中断接收；0：DMA 接收 */
#define USART1_RX_IT_DMA_MODE  1U
```

##### 编译、运行与观测

使用 Keil 打开 `MDK-ARM/STM32F411CEU6.uvprojx`，完整编译并下载。串口助手设置为 115200 baud、8N1、ASCII 模式，每 1 ms 发送一次 `ABCDEFGHIJKLMNOPQRSTUVWXYZ123456`，且不追加换行；随后通过三个 GPIO 的高电平宽度读取耗时。

##### 移植说明

移植到其他 STM32 时，需要重新配置 UART 引脚、DMA Stream/Channel 和 IRQ；SRAM 较小时还应减小测试数组。

## 实验报告

##### 1. 实验背景与原理

- 一次完整的串口中断接收:
  1. 串口外设未接收到任何数据，CPU 正在执行主循环中的业务逻辑
  2. 串口收到第一个字节的数据，硬件自动完成起始位、数据位、停止位的采样，并将这一字节的数据放入 DR 寄存器，同时完成 RXNE 的硬件置位。
  3. 串口向 NVIC 发出中断请求，CPU 保存当前程序运行现场，然后进入 USARTx_IRQHandler 读取相应的串口 DR 寄存器值，并将其放入 SRAM 缓冲区。接着，硬件自动清除 RXNE。CPU 返回之前被串口打断的业务逻辑现场，此时完成串口中断的单字节接收。
  4. 串口每接收一个字节的数据，都会重复完成第二、三步，直到指定字节长度的数据接收完成后，触发 HAL_UART_RxCpltCallback 中断回调。
     - 在中断回调函数中，我们一般会设置有新数据接收完成的标志位，或通知相关线程，以及重新启动下一次接收(`HAL_UART_Receive_IT()` 是一次性、固定长度的接收任务)。
- 一次完整的 DMA 串口接收:
  1. 串口外设未接收到任何数据，CPU 正在执行主循环中的业务逻辑
  2. 串口收到一个字节后，硬件完成起始位、数据位和停止位的采样，将数据写入 USART1 的 `DR` 寄存器，并产生 DMA 接收请求。
  3. DMA 自动读取 DR 寄存器中的数据，并将其搬运到 SRAM 的接收缓冲区。这个过程不需要 CPU 逐字节进入 USARTx_IRQHandler，CPU 可以继续执行主循环业务。
  4. 接收达到缓冲区一半时，DMA 产生半传输中断，进入 DMAX_StreamX_IRQHandler。该配置默认开启，但是可以关闭。
  5. 指定字节长度数据传输完成后，再次进入 DMAx_Streamx_IRQHandler，最终同样会调用 HAL_UART_RxCpltCallback。              
     - 在 HAL_UART_RxCpltCallback 中，我们一般会进行新数据接收完成的标志或通知相关线程，以及重新启动下一次 HAL_UART_Receive_DMA()。
- **接收同样长度的数据，串口中断接收会多次打断 CPU，并且它没有用到 CPU 的 ALU、FPU 等计算能力，而 DMA 只会打断 CPU 两次（最少一次），这样大大提升了 CPU 的利用效率。**
- 我测量某段函数执行时间的方式:在这段程序执行之前，将追踪它的 GPIO 口配置为高电平；在这一段程序执行结束后，配置为低电平。我们使用逻辑分析仪来测量这一个脉冲的时长。

##### 2. 实验假设

**假设**:所有条件相同（硬件、平台、程序、编译条件....）,传输同样长度的数据，串口中断传输的总耗时远大于 DMA 串口传输的耗时。

##### 3. 实验平台与配置

- STM32F411CEU6
- 逻辑分析仪

##### 4. 变量与控制条件

- 自变量：IT 或 DMA 接收模式。
- 因变量：主循环、IRQ Handler、Callback 耗时。
- 控制变量：数据量、发送周期、主频、数组大小、编译选项等其它所有因素。

##### 5. 实验步骤

分别测量并记录在以下三种情况下，主循环业务逻辑、IRQHandler 以及 Callback 的耗时：

1. 没有数据接收
2. 使用串口中断接收
3. 使用 DMA接收

##### 6. 实验数据、分析与结论

| 追踪项目               |   无接收 |                       IT 接收 |                    DMA 接收 |
| ---------------------- | -------: | ----------------------------: | --------------------------: |
| 主循环耗时             | 710.4 µs |                     721.85 µs |                   710.25 µs |
| 1 个接收 IRQ 耗时      |     0 µs | 1.15 µs(前31个)+2.4us(第32个) | 完成 4.65 µs；半传输 1.5 µs |
| 1 个完成 Callback 耗时 |     0 µs |                       0.75 µs |                     2.45 µs |

**IT 使主循环增加 11.45 µs（1.61%）；DMA 与基准只差 0.15 µs，可视为波动。每组 32 Byte 的 IT IRQ 总开销约为 `31 × 1.15 + 2.4 = 38.05 µs`，DMA 的半传输与完成 IRQ 合计约为 `1.5 + 4.65 = 6.15 µs`，*减少约 83.8%*。DMA Callback 虽然更长，但每组只执行一次，因此总体 CPU 开销仍明显低于 IT。第 32 个 IT IRQ 和 DMA 完成 IRQ 已包含各自的 Callback，不能重复相加。**

注：IT 接收和 DMA 接收的主循环耗时，我们记录的是整个主循环都在 IT 接收或 DMA 接收期间完成的。

##### 7. 误差与局限性

所得数据的大小和精度，受被测 MCU 板子的性能、逻辑分析仪的采样率影响。数据上可能会存在一定的误差，但假设得到了验证。
